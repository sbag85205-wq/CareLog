# 공개 체험 사이트 운영 (carelog-public)

QR로 누구나 접속하는 체험용 배포. 기존 `carelog`(Production `main`)와 같은 DB(`carelog-dev`)를 쓰지만, 별도 Vercel 프로젝트에서 `design-v2-soft-glass` 브랜치를 배포합니다.

## 안내 띠

- `carelog-public` Vercel 환경변수에만 `NEXT_PUBLIC_CARELOG_TRIAL_NOTICE=1`.
- 모든 화면 맨 위에 "체험용 공개 사이트예요. 실제 이름·연락처·건강정보는 입력하지 마세요. 체험 기록은 정기적으로 지워져요."가 나옵니다. 인쇄에는 나오지 않습니다.
- 기존 `carelog` 프로젝트에는 이 값이 없으므로 띠가 나오지 않습니다. 빌드할 때 값이 고정되므로, 값을 바꾸면 다시 배포해야 반영됩니다.

## 체험 계정

1. 관리자 화면(`/admin/patients`)에서 등록합니다.
   - 표시 이름에 **`(체험)`**을 붙입니다.
   - **'테스트 계정'**을 체크합니다.
   - 비밀번호를 정해 둡니다. 환자는 스스로 비밀번호를 바꿀 수 없어 방문자가 계정을 잠그지 못합니다.
2. 포스터·현장에는 체험 계정의 아이디·비밀번호만 안내합니다. **관리자 계정은 공개하지 않습니다.**
3. 같은 체험 계정을 쓰는 방문자끼리는 서로의 기록이 보입니다. 안내 띠로 실제 정보 입력을 막습니다.

## 체험 기록 초기화

`.env.trial.local`(Git 제외, `chmod 600`)에 대상을 적습니다.

```
CARELOG_TRIAL_ACCOUNTS=<환자ID>:<Auth사용자ID>,<환자ID>:<Auth사용자ID>
```

```bash
node --env-file=.env.local --env-file=.env.trial.local scripts/reset-trial-data.mjs                 # 미리 보기 (대상·건수)
node --env-file=.env.local --env-file=.env.trial.local scripts/reset-trial-data.mjs --apply --seed  # 삭제 + 가상 예시
```

- 대상 확인을 하나라도 통과하지 못하면 아무것도 지우지 않습니다. 확인 항목은 다음과 같습니다.
  - 설정한 환자ID와 Auth ID 쌍이 DB와 일치
  - 이름에 `(체험)` 표시
  - Auth `carelog_test` 표시
  - 환자 역할
  - 관리자 아님
- 삭제는 `patient_id = 체험 환자` 조건으로만 합니다. 대상 표는 약 기록·경험·복용 체크·선택 공유·진료 질문·건강기록·약 목록·식사·생활 요청·보호자 초대입니다.
- 계정·환자 행·로그인 정보·공유 관계는 남깁니다.
- 끝나면 다시 세어 0건인지 확인합니다.

## 로그인 제한 (공용 와이파이 대비)

- `carelog-public` Vercel 환경변수에만 **`CARELOG_LOGIN_RATE_LIMIT=300`**을 넣습니다. 서버 전용 값이라 화면에 노출되지 않습니다.
  - 같은 IP에서 10분에 300번까지 로그인 요청을 받습니다. 행사장 와이파이처럼 여러 사람이 IP 하나를 쓰는 경우를 위한 값입니다.
  - 이 값을 완화하면 **계정별 비밀번호 실패 제한이 함께 켜집니다.**
    - 같은 IP + 같은 계정에서 10분에 15번 실패하면 그 IP에서 그 계정만 잠시 거부합니다. 같은 와이파이의 다른 계정과 다른 IP의 같은 계정은 영향이 없습니다.
    - 같은 계정이 모든 IP를 합쳐 10분에 60번 실패하면 그 계정을 잠시 거부합니다. 여러 IP로 나눠 대입하는 경우를 막습니다.
  - 10분이 지나면 저절로 풀립니다. 서버 메모리 기준이라 DB에 계정 잠금이 남지 않습니다.
- 값이 없거나 20 이하이면 기존과 같습니다(같은 IP에서 10분 20번, 계정별 제한 없음). 기존 `carelog` 프로젝트에는 넣지 않습니다.
- 막혔을 때:
  - 10분 기다리거나, 새로 배포하면(서버 재시작) 풀립니다.
  - 체험 계정이 막히면 다른 체험 계정을 안내합니다.
- Supabase Auth 자체의 로그인 한도는 대시보드 Authentication → Rate Limits에서 확인합니다. 서버가 대신 로그인하므로 Vercel 서버 IP 기준입니다. 이 값은 기존 CareLog와 함께 쓰므로 바꾸면 양쪽에 적용됩니다.
- 이전 방식(환자 코드) 로그인의 5회 실패 시 15분 잠금은 그대로입니다. 잠긴 경우 관리자 화면의 비밀번호 재설정으로 풀립니다.

## 약 이름 직접 입력

- 약 등록하기 → 약 이름 직접 검색에서 식약처 결과가 없거나 검색을 쓸 수 없으면 **'이름만 직접 입력해 등록'**을 쓸 수 있습니다. 후보가 있어도 '목록에 없어요 · 이름만 직접 입력'을 고를 수 있습니다.
- 직접 입력한 약에는 다음 규칙이 적용됩니다.
  - **'직접 입력'** 표시가 붙습니다. 식약처 후보를 고른 약은 **'식약처 확인'**으로 표시됩니다.
  - 품목기준코드·성분·약 종류를 지어내지 않습니다. 약 종류는 '미분류 · 확인 필요'로 두고, 사용자가 나중에 고를 수 있습니다.
  - 다른 기록과 같은 제품으로 합치지 않습니다.
- '예전 방식으로 적어 둔 약'(보호자 공개용 약 목록, 약 직접 추가) 영역은 기록이 없어도 항상 열 수 있습니다.
