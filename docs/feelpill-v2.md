## 5. 약 등록 (홈 → 약 등록하기)

| 방법 | 동작 | 실제/모의 |
| --- | --- | --- |
| 처방전 촬영·업로드 | 기존 기능을 재사용합니다(사진·PDF, 기기 안 OCR). 처방일·진료과·의료기관·약·횟수·시점·기간·주의사항을 확인 후 저장합니다. 고른 식약처 제품의 성분과 분류도 함께 저장합니다 | 로그인: 실제 OCR + 식약처 허가정보 / 데모: 예제 처방전 |
| 일반약 상자 | 기기 안 OCR로 제품명 후보를 뽑습니다(`product-text.ts`). 식약처 검색으로 후보를 보여 주고 사용자가 고릅니다. 알약 모양 인식은 없습니다 | 로그인: 실제 / 데모: 예제 상자(데모용 예시) |
| 약국 영수증 | 제품 줄만 골라 줄마다 후보를 보여 줍니다. 찾지 못한 줄은 '확인 필요 → 직접 검색'으로 안내합니다. 영수증만으로 복용 처리하지 않습니다 | 로그인: 실제 / 데모: 예제 영수증 |
| 바코드 | **구현하지 않았습니다.** 공개 API로 바코드를 제품 하나에 확실히 연결하는 방법을 검증하지 못했습니다. 추측 없이 직접 검색으로 연결합니다 | — |
| 직접 검색 | 기존 식약처 의약품 제품 허가정보 검색을 재사용합니다(제품명만 전송) | 로그인: 실제 / 데모: 가상 목록 |

처방, 구매(등록), 실제 복용은 서로 다른 상태로 다룹니다.

- 처방은 기본으로 '복용 중'입니다. 일반약은 기본으로 '복용 중 아님'입니다.
- 실제로 먹었다는 기록은 복용 체크와 복용 경험의 '복용한 날'에만 남깁니다.

## 6. 약 종류 자동 분류 (`src/lib/rx/categories.ts`)

1. 식약처 허가정보의 약효 분류 번호(`PRDUCT_TYPE`, 예: `[01140]` → 114 해열·진통·소염제)로 먼저 분류합니다.
2. 식약처 제품 정보의 공식 주성분으로 보강합니다. 예: 이부프로펜은 진통·해열제와 소염진통제에 모두 들어갑니다. 조합제는 여러 종류에 들어갑니다.
3. 근거가 없으면 **미분류 · 확인 필요**로 둡니다. 사용자가 고칠 수 있고, 고치면 근거가 '직접 고름'으로 바뀝니다.
- 제품명, 성분, 함량, 식약처 약효 분류, 사용자용 종류는 서로 다른 칸에 저장합니다.
- AI는 분류에 쓰지 않습니다.
- 심평원 ATC 코드 매핑(공공데이터 파일)은 조사만 했고 아직 연동하지 않았습니다. 다음 단계에서 '기타·미분류'를 줄이는 데 쓸 수 있습니다.

## 7. 복용 경험과 자동 태그 제안 (`src/lib/rx/experience-tagger.ts`)

- 태그 묶음은 세 가지입니다. 도움이 된 점 4개, 복용 후 느낀 불편함 6개, 복용 과정의 불편함 5개에 '원인 미확인' 표시가 더해집니다. 한 경험에 여러 개를 고를 수 있고, 좋은 점과 불편한 점을 함께 고를 수 있습니다.
- **외부 AI는 쓰지 않습니다.** 규칙 기반 제안이 이 기기 안에서만 돌아갑니다. 프로젝트에 AI API 키가 없고 동의 절차도 아직 없습니다.
  - 화면에는 '자동 정리 제안 (규칙 기반 · 외부 AI 사용 안 함)'으로 표시합니다.
  - 예: "두통이 있을 때 먹었는데"처럼 증상이 약을 먹은 이유인 문장은 불편으로 보지 않습니다. "전에는 괜찮았는데"처럼 예전 복용 이야기도 이번 경험에 넣지 않습니다.
- 저장 위치는 칸별로 나뉩니다.
  - 원본 메모: `memo`
  - 사용자가 확정한 태그: `tags`
  - 제안 당시 태그: `suggested_tags`
  - 요약: `summary`. 사용자가 고칠 수 있습니다.
  - 정리 방식: `summary_source = 'rule'`
  - 자동 정리는 원본을 덮어쓰지 않습니다.
- 원인을 단정하지 않습니다. 약 하나에 남긴 경험에는 "약과의 관련성은 확인되지 않음", 처방 전체에 남긴 경험에는 "원인 약물은 확인되지 않음"을 붙입니다.
- **AI 연결 방법 (나중에)**:
  1. `ExperienceTagger` 서버 구현을 추가합니다.
  2. 키는 서버 환경변수에만 둡니다.
  3. 화면에서 '메모 텍스트만 외부 AI로 보냄' 동의를 받습니다.
  4. 메모 텍스트만 보냅니다. 이미지, 처방전 전체, 이름, 생년월일은 보내지 않습니다.
  5. `summary_source = 'ai'`로 저장합니다.

## 8. 찾기

검색은 저장된 태그와 분류만 씁니다. AI는 호출하지 않습니다.

- 약별 찾기는 `filterItems`, 처방·등록별 찾기는 `filterPrescriptions`입니다.
- 같은 제품 판단은 **식약처 품목기준코드가 같을 때만** 합니다(`productKey`). 이름이 같거나 비슷해도, 코드가 없거나 다르면 합치지 않습니다.
- 처방 전체에 남긴 경험은 그 처방의 각 약에서도 보입니다. 이때 "이 약 때문인지는 확인되지 않아요"로 구분해 표시합니다.

## 10. 선택 공유 (함께 보기)

- 모든 기록은 기본 비공개입니다. 사용자가 기록 1건, 수락한 상대 1명, 항목, 기간을 고릅니다.
  - 고를 수 있는 항목: 성분, 함량, 복용 방법·기간, 복용 경험, 진료과·병원(처방만)
  - 제품명과 날짜는 항상 보입니다.
- 상대는 기록 표를 직접 조회할 수 없습니다. DB 함수 `shared_records_for_me()`가 허용한 항목만 담아 돌려주고, 허용하지 않은 항목은 결과에 아예 없습니다. 상대는 읽기만 할 수 있습니다.
- 공유가 멈추는 경우는 네 가지입니다: 공유를 멈출 때, 기간이 끝날 때, 연결(보호자 공유 관계)을 끊을 때, 계정이 비활성화될 때.
- 이전 Preview의 '보호자 공유(visible_to_guardian)' 조회 경로는 항목을 고를 수 없어서 migration 11에서 닫았습니다. 컬럼 값은 보존합니다.

## 12. Preview를 포스터 QR로 공개하려면

Vercel 팀 보호(Standard Protection)로 Preview 주소가 로그인 화면으로 넘어갑니다. Production 설정은 바꾸지 않았습니다. 안전한 순서로 정리하면 아래와 같습니다.

1. **배포별 공유 링크 (권장)**: Vercel → carelog → 해당 Preview 배포 → **Share** 버튼으로 링크를 만듭니다. 그 배포 하나만 로그인 없이 열리고, 대시보드에서 언제든 끌 수 있습니다. QR에는 이 링크(`…?_vercel_share=…`)를 넣습니다. 새로 push하면 새 배포가 생기므로 링크도 다시 만들어야 합니다.
2. Deployment Protection의 'Protection Bypass for Automation' 비밀값은 자동화용입니다. 포스터에 넣지 마세요.
3. Production에 올려 공개하는 방법은 별도 승인 후에 진행합니다.

## 13. 향후 발전 방향 — 병원 시스템 연계 (구현하지 않음)

1. **1단계 (지금)**: 개인 약 복용 경험 기록 — 처방전·일반약 사진으로 등록, 경험 기록, 날짜·종류·진료과별 관리
2. **2단계 (지금, 일부)**: 가족·연인·친구와 선택 공유 — 본인이 고른 기록·항목만
3. **3단계 (미구현)**: 병원 앱·환자 포털과 연계해, 환자가 동의한 처방 이력과 복용 경험을 담당 의료진이 진료 전에 확인. 필요한 기술 확장:
   - 의료기관 협력과 표준 연동: HL7 FHIR `MedicationStatement`·`Observation`·`Consent` 리소스로 내보내기
   - 환자 동의 관리: 기관, 목적, 기간별 동의와 철회 기록, 접근 감사 로그
   - 기관 인증: 기관 계정, OAuth2/SMART on FHIR, 기관별 권한 범위
   - 보안: 전송·저장 암호화, 개인정보 영향평가, 의료법·개인정보보호법 검토
   - 지금의 `shared_records_for_me()`(허용 항목만 돌려주는 함수)와 `record_shares`(기간·철회)는 기관 공유로 넓힐 때 쓸 수 있는 구조입니다.
   - 이 기능은 현재 구현된 것처럼 화면에 표시하지 않습니다. 진료 준비 화면에는 "병원 시스템으로 전송되지 않아요"라고 안내합니다.
